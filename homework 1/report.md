## 題目一：Ackermann Function

## 解題說明

Ackermann Function 是一個很適合用來練習遞迴的問題，因為它會一直呼叫自己，而且計算量會隨著輸入增加而快速變大。

Ackermann Function 定義：

| 條件 | 結果 |
|---|---|
| `m == 0` | `A(m,n) = n + 1` |
| `m > 0` 且 `n == 0` | `A(m,n) = A(m-1,1)` |
| `m > 0` 且 `n > 0` | `A(m,n) = A(m-1,A(m,n-1))` |

這題分成遞迴與非遞迴兩種方式實作，比較兩種方法在資料結構上的差異。

---

## 解題策略

#### 1. 遞迴方法

直接按照 Ackermann Function 的公式寫成函式。

當 `m == 0` 時直接回傳 `n + 1`；如果 `n == 0`，就繼續計算 `A(m-1,1)`；其他情況則先計算 `A(m,n-1)`，再將結果帶入下一層。

這種方法比較簡單，也比較接近數學公式，但會產生很多遞迴呼叫。

#### 2. 非遞迴方法

非遞迴版本使用陣列 `st` 搭配 `top` 來模擬 Stack。

因為遞迴程式會使用系統的 Call Stack，所以改成非遞迴後，需要自己用陣列記錄還沒有完成的工作。

`top` 用來表示目前陣列的頂端位置，透過增加或減少 `top` 來管理資料。

---

## 程式實作

### 遞迴版本

```cpp
#include<iostream>
using namespace std;
int A(int m, int n)
{
	if (m == 0) { return n + 1; }
	else if (m > 0 && n == 0) { return A(m - 1, 1); }
	else if (m > 0 && n > 0) { return A(m - 1, A(m, n - 1)); }
}
int main()
{
	int a, b;
	while (cin >> a >> b)
	{
		cout << A(a, b) << endl;
	}
	return 0;
}
```

## 程式說明

- `A(m,n)` 是 Ackermann Function。
- `m == 0` 時直接得到答案。
- `n == 0` 時呼叫下一層遞迴。
- `m > 0` 且 `n > 0` 時會產生兩層遞迴關係。
- `main()` 使用 `while` 讀取輸入資料，並輸出結果。

---

### 非遞迴版本

```cpp
#include<iostream>
using namespace std;
int A(long m, long n)
{
	long st[10000];
	int top = -1;
	st[++top] = m;
	while (top >= 0)
	{
		m = st[top--];
		if (m == 0)
		{
			n = n + 1;
		}
		else if (n == 0)
		{
			st[++top] = m - 1 ;
			n = 1;
		}
		else
		{
			st[++top] = m - 1; //先把A(m-1,結果)記住
			st[++top] = m; //再算A(m-1,A(m,n-1))裡的A(m,n-1)
			n = n - 1;
		}
	}
	return n;
}
int main()
{
	int x, y;
	cout << "輸入(x,y):" << endl;
	cin >> x >> y;
	cout << A(x,y);
	return 0;
}
```

## 程式說明

這個版本不直接使用遞迴，而是利用陣列 `st` 和 `top` 來模擬 Stack。

當程式遇到需要之後再處理的工作，就先放進陣列中。`top` 則負責記錄目前最後一筆資料的位置。

這樣可以用資料結構的方式模擬原本遞迴程式使用的 Call Stack。

---

## 效能分析

### 遞迴版本

Ackermann Function 的遞迴次數會隨著 `m` 和 `n` 增加而快速成長，因此計算量也會快速增加。由於每次遞迴呼叫都需要保留目前的執行狀態，所以會使用到 Call Stack。

- **時間複雜度**：隨著輸入增加而快速成長，無法用一般簡單的多項式複雜度表示。
- **空間複雜度**：主要來自遞迴呼叫所使用的 Call Stack，遞迴層數越深，所需空間越多。
- **優點**：程式寫法簡單，而且和 Ackermann Function 的數學定義很接近。
- **缺點**：輸入稍微變大，遞迴呼叫次數就會快速增加。

### 非遞迴版本

非遞迴版本使用陣列 `st` 和 `top` 來模擬 Stack，因此不需要依靠函式本身一直進行遞迴。雖然可以避免大量的函式呼叫，但實際上仍然需要處理和遞迴版本相同的計算關係。

- **時間複雜度**：同樣會隨輸入增加而快速成長。
- **空間複雜度**：使用固定大小的 `st[10000]` 陣列來儲存尚未完成的工作。
- **優點**：不使用函式遞迴，可以自己控制 Stack 的資料。
- **缺點**：程式比遞迴版本複雜，而且陣列大小有限。

### 兩種方法比較

| 方法 | 時間複雜度 | 空間使用 | 特點 |
|---|---|---|---|
| 遞迴 | 隨輸入快速增加 | 使用 Call Stack | 程式簡單、容易理解 |
| 非遞迴 | 隨輸入快速增加 | 使用陣列模擬 Stack | 不依靠遞迴、自己管理資料 |

這次實作讓我比較清楚了解遞迴其實和 Stack 有很大的關係。遞迴版本是交給系統幫我們管理呼叫順序，而非遞迴版本則是自己利用陣列和 `top` 來管理。

## 題目二：Power Set（冪集合）

## 解題說明

Power Set 是一個集合中所有子集合的集合。

例如輸入：

```text
ABC
```

每個字元都有「選擇」或「不選擇」兩種可能，所以總共有：

```text
2^3 = 8
```

個子集合。

---

## 解題策略

本題使用遞迴來處理每個字元。

對目前的字元有兩種選擇：

1. 不加入目前字元。
2. 加入目前字元。

程式先處理「不加入」，再使用 `push_back()` 將字元加入 `a`，接著處理「加入」的情況。

處理完成後使用 `pop_back()` 把最後加入的字元移除，讓程式回到上一個狀態。

這個過程和資料結構中的 Stack 以及 Backtracking（回溯）概念有關。

---

## 程式實作

```cpp
#include <iostream>
#include <string>
using namespace std;
string a;
void P(string s, const int m, const int n)
{
    if (m == n)
    {
        cout << "{ ";
        for (int i = 0; i < a.size(); i++)
        {
            cout << a[i];
        }
        cout << " }" << endl;
    }
    else
    {
        P(s, m + 1, n);
        a.push_back(s[m]);
        P(s, m + 1, n);
        a.pop_back();
    }
}
int main()
{
    string s;
    if (cin >> s)
    {
        int t = s.size();
        P(s, 0, t);
    }
    return 0;
}
```

---

## 程式說明

`a` 用來記錄目前選擇的字元。

當 `m == n` 時，代表所有字元都已經決定要不要選擇，因此把目前的子集合輸出。

主要流程是：

```cpp
P(s, m + 1, n);
a.push_back(s[m]);
P(s, m + 1, n);
a.pop_back();
```

可以簡單理解成：

```text
不選目前字元
↓
選目前字元
↓
處理完成後把字元移除
```

這樣就可以把所有可能的子集合找出來。

---

## 效能分析

如果輸入有 `n` 個字元，每個字元都有選與不選兩種可能，因此會產生：

```text
2^n
```

個子集合。

如果把每個子集合的輸出也算進去，整體時間大約為：

```text
O(n × 2^n)
```

遞迴深度最多為 `n`，因此遞迴所需要的空間大約為：

```text
O(n)
```

---

## 測試與驗證

輸入：

```text
ABC
```

輸出：

```text
{  }
{ C }
{ B }
{ BC }
{ A }
{ AC }
{ AB }
{ ABC }
```

共有 8 個結果，符合：

```text
2^3 = 8
```

因此可以確認程式能正確產生 Power Set。

---

### 結論

Power Set 的重點是每個元素都有「選」和「不選」兩種可能。使用遞迴後，可以很自然地把這兩種選擇分開處理。

這次也讓我了解到 `push_back()` 和 `pop_back()` 不只是單純增加或刪除資料，也可以搭配遞迴來保存目前的狀態，再在處理完之後恢復原本的狀態。

## 申論及開發報告

這次作業主要練習的是**遞迴和資料結構之間的關係**。

在 Ackermann Function 中，遞迴函式會不斷產生新的函式呼叫，而這些呼叫其實就是由 Call Stack 幫忙管理。當改成非遞迴版本後，就需要自己使用陣列和 `top` 來模擬 Stack。

Power Set 則是另一種遞迴的應用。每個元素都有兩種選擇，因此可以形成一個二元的選擇過程。程式利用 `push_back()` 和 `pop_back()` 保存及恢復目前的資料，這也和 Backtracking 的概念有關。

透過這次作業，我比較能理解資料結構不是只有陣列、Stack 這些獨立的東西，也可以和遞迴結合在一起解決問題。尤其是非遞迴的 Ackermann Function，讓我更明白遞迴背後其實有 Stack 在幫忙管理。
