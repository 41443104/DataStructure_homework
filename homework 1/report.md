# 題目一：Ackermann Function

## 解題說明

Ackermann Function 是一個常見的遞迴練習題，主要是讓我們了解函式如何一直呼叫自己。

它的特點是當輸入的數值變大時，計算的次數也會快速增加，所以很適合用來觀察遞迴的執行方式。

Ackermann Function 定義如下：

| 條件 | 結果 |
|---|---|
| `m == 0` | `A(m,n) = n + 1` |
| `m > 0` 且 `n == 0` | `A(m,n) = A(m-1,1)` |
| `m > 0` 且 `n > 0` | `A(m,n) = A(m-1,A(m,n-1))` |

這次作業分別使用「遞迴」和「非遞迴」兩種方式來完成，並比較兩種方法在資料結構上的差異。

---

## 解題策略

### 1. 遞迴方法

遞迴版本直接按照 Ackermann Function 的公式來寫。

先判斷 `m` 和 `n` 的值，如果符合基本條件就直接得到結果；如果還不能得到答案，就繼續呼叫 `A()`。

這種寫法比較接近題目的數學公式，所以比較容易理解。

### 2. 非遞迴方法

非遞迴版本不能直接呼叫自己，因此使用陣列 `st` 和 `top` 來模擬 Stack。

原本遞迴時，系統會幫我們記住還沒完成的函式。改成非遞迴後，就改成自己使用陣列把這些工作記錄下來。

---

## 程式實作

### 遞迴版本

```cpp
#include<iostream>
using namespace std;
int A(int m, int n)
{
	if (m == 0) { return n + 1; }
	else if (m > 0 && n == 0) { return A(m - 1, 1); }
	else if (m > 0 && n > 0) { return A(m - 1, A(m, n - 1)); }
}
int main()
{
	int a, b;
	while (cin >> a >> b)
	{
		cout << A(a, b) << endl;
	}
	return 0;
}
```

### 程式說明

程式中的 `A()` 就是 Ackermann Function。

當 `m == 0` 時，直接回傳 `n + 1`。

如果 `n == 0`，就呼叫：

```cpp
A(m - 1, 1)
```

其他情況則會再進行遞迴計算。

`main()` 使用 `while` 讓程式可以連續讀取輸入資料。

---

### 非遞迴版本

```cpp
#include<iostream>
using namespace std;
int A(long m, long n)
{
	long st[10000];
	int top = -1;
	st[++top] = m;
	while (top >= 0)
	{
		m = st[top--];
		if (m == 0)
		{
			n = n + 1;
		}
		else if (n == 0)
		{
			st[++top] = m - 1 ;
			n = 1;
		}
		else
		{
			st[++top] = m - 1; //先把A(m-1,結果)記住
			st[++top] = m; //再算A(m-1,A(m,n-1))裡的A(m,n-1)
			n = n - 1;
		}
	}
	return n;
}
int main()
{
	int x, y;
	cout << "輸入(x,y):" << endl;
	cin >> x >> y;
	cout << A(x,y);
	return 0;
}
```

### 程式說明

這個版本沒有使用遞迴，而是利用 `st` 陣列來保存還沒有處理完的資料。

`top` 可以想成 Stack 的頂端位置。

當需要保存資料時，就把資料放到 `st` 裡；處理資料時則利用 `top` 找到目前要處理的內容。

所以這個版本主要是在練習如何使用陣列來模擬 Stack。

---

## 效能分析

### 遞迴版本

Ackermann Function 的計算量增加得非常快，當輸入變大時，需要進行的遞迴呼叫也會增加很多。

- **時間複雜度**：計算量會隨輸入快速增加，不能用一般簡單的 `O(n)` 或 `O(n²)` 來表示。
- **空間複雜度**：會使用 Call Stack 保存每一層遞迴的資料，因此遞迴越深，需要的空間也越多。
- **優點**：程式比較短，也很接近題目的公式。
- **缺點**：輸入變大後，遞迴次數會快速增加。

### 非遞迴版本

非遞迴版本改用 `st` 陣列和 `top` 管理資料，不需要一直建立新的函式呼叫。

- **時間複雜度**：因為還是需要完成 Ackermann Function 原本的計算，所以計算量一樣會快速增加。
- **空間複雜度**：使用 `st[10000]` 儲存尚未處理的資料，因此空間大小受到陣列容量限制。
- **優點**：不用依靠系統的遞迴 Stack，可以自己管理資料。
- **缺點**：程式比遞迴版本複雜，而且陣列大小是固定的。

### 方法比較

| 方法 | 時間 | 空間 | 特點 |
|---|---|---|---|
| 遞迴 | 計算量快速增加 | 使用 Call Stack | 寫法簡單 |
| 非遞迴 | 計算量快速增加 | 使用 `st` 陣列 | 自己管理 Stack |

從這兩種方法可以看到，遞迴和 Stack 有很大的關係。遞迴版本是由系統幫忙管理，而非遞迴版本則是自己利用陣列來處理。

# 題目二：Power Set（冪集合）

## 解題說明

Power Set 是指一個集合裡面所有可能的子集合。

例如輸入：

```text
ABC
```

每一個字元都有「選」和「不選」兩種可能。

因此有 3 個字元時，總共有：

```text
2^3 = 8
```

個子集合。

這題主要利用遞迴來把每一種可能都找出來。

---

## 解題策略

每次處理一個字元時，都會有兩種選擇：

1. 不加入這個字元。
2. 加入這個字元。

程式先處理不加入的情況，再利用 `push_back()` 將字元加入目前的集合。

加入後再繼續往下一層遞迴。

等這一條路處理完，再利用 `pop_back()` 把剛剛加入的字元移除，回到原本的狀態。

這種「先做選擇，完成後再恢復」的方式就是 Backtracking 的概念。

---

## 程式實作

```cpp
#include <iostream>
#include <string>
using namespace std;
string a;
void P(string s, const int m, const int n)
{
    if (m == n)
    {
        cout << "{ ";
        for (int i = 0; i < a.size(); i++)
        {
            cout << a[i];
        }
        cout << " }" << endl;
    }
    else
    {
        P(s, m + 1, n);
        a.push_back(s[m]);
        P(s, m + 1, n);
        a.pop_back();
    }
}
int main()
{
    string s;
    if (cin >> s)
    {
        int t = s.size();
        P(s, 0, t);
    }
    return 0;
}
```

---

## 程式說明

`a` 是用來記錄目前已經選擇的字元。

當：

```cpp
m == n
```

代表所有字元都已經處理完，所以把目前的 `a` 印出來。

主要的程式是：

```cpp
P(s, m + 1, n);
a.push_back(s[m]);
P(s, m + 1, n);
a.pop_back();
```

可以把它想成：

```text
先不選
    ↓
繼續處理
    ↓
再選
    ↓
繼續處理
    ↓
把選的東西拿掉
```

一直重複這個過程，就可以找到所有子集合。

---

## 效能分析

假設輸入有 `n` 個字元。

每個字元都有兩種選擇，所以總共有：

```text
2^n
```

種結果。

因此產生所有子集合的數量會隨著 `n` 增加而快速增加。

- **時間複雜度**：如果包含輸出每個子集合的時間，大約是 `O(n × 2^n)`。
- **空間複雜度**：遞迴最多進行 `n` 層，因此大約需要 `O(n)` 的遞迴空間。

---

## 測試與驗證

輸入：

```text
ABC
```

程式輸出：

```text
{  }
{ C }
{ B }
{ BC }
{ A }
{ AC }
{ AB }
{ ABC }
```

總共有 8 個結果：

```text

```

所以結果數量符合 Power Set 的規則。

## 結論

Power Set 這題讓我比較了解遞迴的另一種使用方式。

每個字元都可以選或不選，所以可以把問題一直分成兩條路。

另外，使用 `push_back()` 加入資料，再使用 `pop_back()` 恢復原本的狀態，也讓我比較了解 Backtracking 的概念。

---

## 申論及開發報告

Power Set 和前面的 Ackermann Function 雖然都是使用遞迴，但是解題方式不太一樣。

Ackermann Function 比較像是按照公式一直往下算，而 Power Set 則是一直做「選或不選」的決定。

在 Power Set 中，我覺得比較重要的是回復資料這個部分。

例如目前選了 `A`，處理完 `A` 的情況後，要把 `A` 移除，才能去處理沒有 `A` 的其他情況。

所以 `push_back()` 和 `pop_back()` 在這裡就可以幫助程式保存和恢復目前的狀態。

這次作業讓我發現遞迴不只是函式自己呼叫自己，也可以搭配 Stack、陣列和 Backtracking 來解決不同類型的問題。
